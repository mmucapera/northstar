# dataset_oilandgas Ops — Oil & Supply Chain Dashboard

Full source export. Stack: React 19 + TanStack Start v1 (file-based routing, SSR) + Vite 7 + Tailwind CSS v4 + shadcn/ui.

## Run in VS Code

```bash
npm install      # or bun install / pnpm install
npm run dev      # http://localhost:8080
npm run build
```

Recommended VS Code extensions: ESLint, Tailwind CSS IntelliSense.

## Where things live

| Path | Purpose |
| --- | --- |
| `src/styles.css` | Design system: dark "Terminal Command Deck" theme, color tokens, fonts (Inter + JetBrains Mono) |
| `src/routes/__root.tsx` | Shell layout, nav, font preconnects, global meta |
| `src/routes/index.tsx` | Dashboard home: KPI cards, production trend chart, regional inventory, alerts |

| `src/routeTree.gen.ts` | Auto-generated by the router plugin. Never edit. |

## Design → data links

Every visual reads from a named export in `src/lib/mock-data.ts`:

| UI element | Data export | SQL table |
| --- | --- | --- |
| KPI cards + sparklines | `KPIS[range]` | `kpi_snapshots` |
| Production trend chart | `PRODUCTION_TREND[range]` | `production_trend` |
| Regional inventory bars | `REGION_INVENTORY[range]` | `region_inventory` |
| Shipments table / CSV | `SHIPMENTS`, `shipmentsCsv()` | `shipments` |
| Alerts panel | `ALERTS` | `disruption_alerts` |
| Inventory page tanks | `TANKS` | `tanks` (+ `region_tank_rollup` view) |

The range switcher (`24H` / `7D` / `30D`) is React state in `src/routes/index.tsx`; it keys into the `Record<RangeKey, …>` maps above.

## Moving from mock data to a real database

1. Run `dataset_oil.sql` against any PostgreSQL 14+ / Supabase project. It creates the enums, tables, indexes, a roll-up view, grants, RLS policies, and inserts the exact rows the mock file contains.
2. Replace each import from `@/lib/mock-data` with a query. Keep the exported TypeScript types — the column names map 1:1 (camelCase in TS, snake_case in SQL).
3. Recommended read shape in TanStack Start: fetch in the route `loader` via `context.queryClient.ensureQueryData(...)` and read with `useSuspenseQuery(...)` in the component, so SSR stays intact.
